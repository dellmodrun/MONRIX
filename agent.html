Agent: automation that can propose, and nothing else« on: today »

An optional helper. You write a rule in plain English, such as "when my profit passes $500, suggest moving 30% into Monero". It watches your balances and, when the condition is met, it suggests the move. It cannot move money. You click approve, and the app opens the normal screen with the numbers filled in for you to do it yourself.

How to use it

  1. Turn it on in Settings. It is off by default.
  2. Type a rule in the chat box, or build one from the dropdowns: a condition, an action, and how often it may fire.
  3. When a rule fires, a proposal appears with the exact amount and the reason. Approve or dismiss.
  4. Approving opens the Exchange, Terminal or Vault screen prefilled. You still press the final button.

The plain-English part uses Claude, an AI model, and needs an API key you add yourself. If you would rather not involve an AI company at all, leave the key empty: the rules built from dropdowns work without it, and nothing is sent anywhere.

The one promise
The agent has no access to your keys, your wallets or the swap services. It can only write a suggestion on your screen. This is enforced in the code, not by a setting.

Rules, technically

A rule is a trigger, an action and a cooldown. Triggers are evaluated against a snapshot assembled from live data: prices, balances per asset, P&L.

Triggersrealised P&L above · SOL balance above · allocation above or below a percentage (SOL, USDC, XMR, ZEC, tokens) · price above or below · transparent ZEC above · treasury value above
Actionspropose a cross-chain move (opens Exchange prefilled) · propose a Solana swap (opens Terminal prefilled) · propose shielding ZEC (opens Vault) · notify
Safeguardscooldown of at least 60 s · one pending proposal per rule · proposals above agent.max_proposal_usd flagged · engine off by default

Example

# you type "When realised profit exceeds $500, propose moving 30% into XMR." # it becomes trigger realized_pnl_above: 500 action propose_move: SOL → XMR, 30% cooldown 3600s

When it fires, a proposal appears with the concrete amount and the rule's reasoning. Approve, and Exchange opens with the route and amount filled in.

Re: Agent — technical details: natural language, and what is sent to Anthropic« Reply #1 »
  • Claude (default claude-opus-5-5, configurable) receives a system prompt describing the rule schema and the constraints, recent chat, and the current snapshot, and answers in a strict JSON shape: reply, suggested rules, one-off proposals.
  • Suggested rules are validated in Rust against the schema. Invalid ones are shown as rejected, not silently corrected.
  • The API key is a vault secret. Requests go through the tunnelled client. Model, token counts and results are written to the audit table.
  • The model is instructed, and the code enforces, that it cannot execute anything and must never ask for seeds or keys.

What is sent to Anthropic

The snapshot shown in the Agent view: prices, balances per asset, P&L, your existing rules, and your message. Not addresses, not keys, not transaction history. If that exceeds your threat model, leave the key unset; the rules engine works without it.

No signing power is not a setting. The agent module holds no reference to the signer, the wallet RPCs or the exchange order functions. See src-tauri/src/agent.rs.
